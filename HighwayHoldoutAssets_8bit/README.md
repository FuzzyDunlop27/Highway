# Highway Holdout — 8-bit edition

A separate **57-asset pixel-art version** of the original pack. All 21 P1, 30 P2 and 6 optional P3 assets are included. Names, master canvas sizes, footprints and centered rotation pivots are compatible with the original set.

## Use with Claude

Give Claude this folder or ZIP and `CLAUDE_HANDOFF.md`. The pack includes its own Xcode catalog, so the artwork can be integrated without smoothing or trimming. Use only one art variant in the app at a time; the resource names deliberately match.

Start with `previews/07_gameplay_art_mockup.png`, then `previews/09_style_comparison.png` for the two versions together.

## The style

- A 32×32 logical grid for each 128×128 world tile: each drawn pixel becomes a solid 4×4 block.
- 64×64 logical grids for 2×2 buildings; 96×96 for the HQ.
- HUD icons use a 32×32 logical grid enlarged 8× to 256×256. App icon layers use 128×128 enlarged 8× to 1024×1024.
- Sixteen solid colors, taken from the original specification, with no antialiasing or blended edge colors. Transparent pixels use alpha 0; visible pixels use alpha 255.
- Chunky silhouettes, stepped diagonals, simple shading and patterned dust. Terrain, characters, several defenses and effects were redrawn directly on the small pixel grid. Other objects adapt the editable v1 geometry to the grid.
- This is an 8-bit-inspired visual style, not an emulation of a particular console's palette or hardware restrictions.

## Rendering

Use **nearest-neighbor** filtering. Preserve transparent padding. Load the existing snake_case image names, then set world sizes explicitly from the game's tile size. The catalog follows the repository convention of a 32-point tile at @1x; the loose PNG masters still measure 128 pixels per tile.

The current repository importer normalizes, trims and applies Lanczos resampling. Its `--dry-run` checks these names successfully, but its normal conversion is unsuitable for this finished pixel set. Use the supplied catalog. The original pack and game source have not been replaced.

The two icon layers reconstruct the flattened app icon exactly. They are source layers, not an Icon Composer `.icon` project.

## Validation

The pack passes 460 asset checks, including exact filenames/sizes, embedded sRGB profiles, alpha, padding, seamless borders, palette membership, integer pixel blocks and icon-layer reconstruction. All 169 catalog renditions match their nearest-neighbor reference images. The catalog also compiles for iPhone and iPad with local Xcode `actool`.

The style anchor, category sheets, 48px review, terrain repetitions, rotation overlays and composed scene were visually inspected. These are asset checks; the game has not been built or playtested with this variant.

## Rebuild or edit

Requirements are the same already-available authoring tools used for v1: Node.js with `sharp`, Python with Pillow. No runtime game dependency is added. Preview labels use macOS Arial fonts; adjust the font paths in `package_assets.py` on other platforms.

```sh
node scripts/render_layouts.cjs
python3 scripts/build_pixel_assets.py
python3 scripts/package_assets.py
python3 scripts/validate_catalog.py
```

Set `NODE_PATH` if `sharp` resides outside the normal Node module path. Use a Python interpreter with Pillow installed.

Edit native drawings in `scripts/pixel_units.py`, `pixel_world.py`, or `pixel_defenses.py`. Other objects use the editable geometry in `reference/vector_layouts/`. The resulting `source_svg/` files consist entirely of pixel rectangles and can also be edited manually. Rebuilding overwrites manual output edits. Keep edited PNGs on their native grid and enlarge with nearest-neighbor.

The v1/v2 comparison sheet is a delivery preview and is not regenerated by the standalone build scripts, which do not require the original pack to be present.
